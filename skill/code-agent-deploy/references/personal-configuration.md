# 个人项目参数与密钥

## 产品规则

每个项目只有一个所有者；同一平台可以托管多个用户各自的个人项目。项目所有者管理自己的部署、日志和参数，不设计团队、协作者、审批流或按测试/生产区分的配置负责人。每个项目一套线上配置，不区分环境。项目所有者即创建该项目时所用部署密钥对应的开发者。

正常操作为“一次部署，自动携带已声明的项目运行参数；之后复用平台参数”。参数页面只作为查看与手动修改入口，不是每次部署必经步骤。

## 首次部署

1. 本地技能识别项目确实需要的运行参数，按下节“线上值与本地值不同的两类参数”确定每个参数的来源（本地文件、平台生成或用户手动输入），不打印密钥值。
2. 部署授权覆盖该项目已声明且选定的运行参数提交；来源与字段明确时无需另开审批。未明确的机器级凭据、其他项目文件或无关密钥不在范围内。
3. 从明确选择的本地配置读取值，由 appcli 提交给平台加密保存。参数不进入镜像、镜像压缩包或明文 manifest。
4. 平台保留参数（PORT、HOSTNAME、PUBLIC_URL、DATABASE_URL、UPLOAD_DIR、GENERATED_DIR）由平台按 [appcli 使用参考](appcli-reference.md) 第 2.2 节注入，用户参数不能声明。每次部署使用绑定的参数版本启动。
5. 创建部署时，平台按 spec 中的 env 声明检查必填项；缺失时返回 `CONFIG_MISSING_REQUIRED` 和缺失名单。
6. 仅当必填值缺失或本地值不适用于服务器时，提示所有者补齐；可在本地补充或使用平台参数页面，不强制跳转网页。

不要把 .env.local 整个文件盲目上传。只提交已声明的业务运行参数，排除镜像仓库凭据、部署密钥与令牌、私钥和其他项目变量。dotenv 文件作为数据解析，不能 source 执行。

localhost 地址、开发机绝对路径及本地回调 URL 往往不能在线上使用，发现时明确标注并按项目或平台实际配置处理，不猜测服务器地址。

## 线上值与本地值不同的两类参数

本地开发时的值不一定适合放到共享给他人的线上环境。首次提交时按下表区分：

| 类型 | 例子 | 线上值从哪来 | manifest 写法 |
|---|---|---|---|
| 应用自用的签名密钥 | SESSION_SECRET、JWT_SECRET、NEXTAUTH_SECRET、AUTH_SECRET、COOKIE_SECRET | 平台生成新的随机值，不沿用本地值 | `generate` |
| 用于解密已存数据的密钥 | ENCRYPTION_KEY、数据加密密钥 | 迁移了本地数据时必须沿用本地值，否则旧数据无法解密；不迁移数据时可以 `generate` | 迁移数据时用 `source` 指向本地文件，否则 `generate` |
| 第三方服务凭据 | OPENAI_API_KEY、支付密钥、短信/邮件服务密钥、OAuth Client Secret | 由用户决定：沿用本地值，或换成专门给线上用的凭据 | 沿用：`source`；另用：`manual` |
| 普通配置 | 第三方服务地址、功能开关 | 本地值；是 localhost 或本机路径时询问线上值 | `source` |

规则：

- 签名密钥默认由平台生成：本地值可能已经出现在代码库、截图或聊天记录中。线上用新值的影响只是让旧会话失效，对首次上线没有影响。生成的明文不经过开发机和 AI，也不显示在任何页面。
- 第三方凭据首次提交前必须问用户：“这些凭据是开发测试用的吗？上线后其他人使用应用会消耗这个账号的额度或产生费用。”用户选择另用凭据时，标为 `manual`，请用户自己在终端执行 `appcli config set <名称>` 输入，AI 不经手明文。
- 判断不了某个变量属于哪类时，按第三方凭据处理，问用户。
- 轮换签名密钥：`appcli config regenerate <名称>` 后 `appcli config apply`，会让已登录用户全部掉线，执行前告诉用户。用于解密数据的密钥不能轮换，否则旧数据无法解密。

## 后续部署与页面修改

- 平台已有值优先；普通部署只补充新增且缺失的声明参数，不覆盖已有值。
- 本地删除某个变量不自动删除平台值。用户明确要求同步修改或删除时，才更新对应字段。
- 所有者通过 `appcli console` 获取一次性登录链接进入参数页面，无需另设密码。也可直接使用 `appcli config get/set/unset/apply`。
- 平台页面提供参数名、普通值、敏感标记和编辑入口。敏感值默认掩码；空白表示保持原值，设置空值与删除是两个明确动作。
- 所有者在页面修改时可“保存”或“保存并应用”。仅保存不重启；保存并应用会重建对应容器并健康检查，失败时恢复原配置。无需重新构建镜像。
- 显示已保存版本与正在运行版本；应用失败时保留清楚的状态和日志。不要把保存成功报告成已生效。
- 构建时公开变量（NEXT_PUBLIC_* 等）不属于运行参数，不在参数页面管理：在 manifest 的 buildEnv 中声明，由 appcli 构建时传入，修改后需要重新部署。密钥不能放进 buildEnv。

## 使用约束

- `appcli config get` 返回已保存版本、正在运行版本、各参数的属性和是否已设置；不返回敏感明文。
- 普通部署只写入平台上不存在的参数，不覆盖已有值；`appcli config set/unset/regenerate` 基于当前版本修改，版本已被别人改过时返回 `CONFIG_CONFLICT`，重新读取后再改，不能静默覆盖。
- `appcli config apply` 让已保存的参数生效；项目没有运行版本时返回 `APPLICATION_NOT_RUNNING`，已保存的参数在下次部署时使用。部署记录会标明所使用的参数版本。
- 日志中的敏感值由平台按该项目当前的敏感参数值替换。
- 只有项目所属的开发者能读取和修改参数。敏感值在平台加密保存。
- 变量名须匹配 `^[A-Z_][A-Z0-9_]{0,63}$`，值不含 NUL，单值 ≤ 16KB，合计 ≤ 64KB。参数不会写进镜像，部署日志只记录参数名称与版本。

验收：首次带入声明参数可启动；第二次部署保留平台编辑值；新增必填项缺失时提示；另一账号无法访问；日志和镜像无密钥；保存/应用版本准确；公开构建参数修改会提示重新构建。
